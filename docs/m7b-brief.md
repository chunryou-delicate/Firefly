의존성: **numpy만.** 새 패키지 금지. 아타리 묶음(ALE)은 승인 전이므로 이번 범위가 아니다. 다만 아래 게임 인터페이스는 나중에 ALE 게임을 그대로 끼울 수 있게 설계한다.

## 왜
초파리 뇌를 붙이기 전에 **게임과 비교 대상이 먼저 있어야 한다.** 뇌 없는 봇과 무작위 봇의 점수가 정해져 있어야 초파리 점수가 의미를 갖는다. 뇌 연결은 M7a 결과를 보고 M7c에서 한다.

## 만들 것
```
flysim/apps/games/
  base.py      # GameEnv 인터페이스: reset(seed) -> frame, step(action) -> frame, reward, done, info
               #   frame은 uint8 회색조 84x84 (ALE 관례와 같게). 한 틱 = 1/60 s. 같은 시드면 같은 판.
  jump.py      # 첫 게임 "뛰어넘기": 장애물이 앞에서 다가오고 점프로 넘는다. 점수 = 넘은 장애물 수. 부딪히면 끝.
               #   속도는 판이 진행될수록 단계적으로 빨라진다(규칙은 코드 상수로 고정).
  dodge.py     # 두 번째 게임 "피하기": 물체가 왼쪽 또는 오른쪽에서 다가오고 반대쪽으로 피한다.
  runner.py    # 에이전트를 받아 N판 돌리고 점수 분포를 낸다. 결과는 json.
  agents.py    # RandomAgent, ThresholdAgent(뇌 없는 봇). BrainAgent 자리만 비워둔다(M7c).
flysim/sensory/looming.py   # 화면 → 좌·우 "다가옴" 신호
flysim/probe/motor.py       # (자리만) 뉴런 스파이크 → 행동 해독기. 인터페이스와 테스트만, 실제 연결은 M7c
tests/test_games.py
docs/m7b-report.md
```

## 핵심 요구
1. **감지기는 화면 픽셀만 본다.** 게임 내부 상태(장애물 좌표 등)를 읽으면 안 된다. 초파리가 받는 것과 같은 것만 받아야 뇌 없는 봇과 공정하게 비교된다. 화면을 좌우 반으로 나눠, 밝기가 바뀐 영역의 크기가 프레임마다 얼마나 커지는지를 "다가옴" 신호로 쓴다. 구체적 계산은 네가 정하되 리포트에 식을 적고 "가정"으로 표시한다.
2. **같은 눈, 같은 근육.** `looming.py`의 출력(좌·우 두 값)과 행동 공간(아무것도 안 함 / 점프 / 왼쪽 / 오른쪽)은 두 게임에서 같다. 게임마다 감지기를 바꾸지 않는다.
3. **뇌 없는 봇의 임계값**: 시드 0~9에서 격자로 가장 좋은 임계값을 고르고, 시드 10~19로 평가한다. 고른 값과 두 시드 묶음의 점수를 둘 다 적는다. 이 봇은 **강해야** 한다 — 초파리가 넘어야 할 벽이다.
4. **무작위 봇**: 같은 행동 공간 균일 무작위, 시드 10~19.
5. **결정론**: 같은 시드 → 같은 프레임 열, 같은 점수. 테스트로 강제한다.
6. **사람이 볼 수 있게**: 한 판을 PNG 프레임 묶음 또는 짧은 GIF로 떨군다. numpy로 직접 쓰거나 이미 있는 의존성만 쓴다. 안 되면 프레임 npz만 남기고 보고한다.
