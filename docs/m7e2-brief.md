# M7e2 — 분할 화면이 재대결 묶음을 바르게 보이게

총괄 세션 작성 (2026-10-25). 재생 화면 손질이다. 실험이 아니므로 결과에 영향이 없다.

> **보고 대상:** 총괄 세션. 이 지시를 전달한 메시지의 `from-name`을 쓴다.

먼저 읽을 것: `docs/m7e-brief.md`, `docs/m7c2-report.md` 6절, `runs/m7c2/*-brain-seed10/`(묶음 3개), `flysim-3d.html`의 재생 모드.

## 문제
M7e 재생 화면은 M7c 묶음에 맞춰져 있다. 재대결(M7c2) 묶음을 열면 세 군데가 틀리게 보인다.
1. **과도 구간 띠.** `RESET_TRANSIENT_MS` = 2000을 무조건 칠한다. M7c2 묶음은 예열 5 s 뒤부터 기록했으므로(`run.json` `meta.warmup_steps` = 5000) 그 띠는 거짓이다. 통계 설명 문구의 "묶음에 예열이 없어"도 마찬가지다.
2. **주황/보라 분류 창.** "입력 동반"을 직전 50 ms(M7c 해독기 창)로 잰다. M7c2 해독기 창은 300 ms다.
3. **행동 재계산 검사.** 화면이 거대 신경섬유 스파이크로 행동을 다시 계산해 기록과 대조한다. 이 계산이 M7c 규칙(한 발)이면 M7c2 묶음에서 어긋난다.

## 할 일
- 해독기 규격을 `game.json`의 `agent.decoder`에서 읽는다.
  - `CountWindowDecoder`: `window_ms`, `min_spikes`
  - `GiantFibreDecoder`: `window_ms`, 한 발 (= `CountWindowDecoder(window_ms, 1)`)
  - 그 밖의 값이면 재계산 검사를 끄고 "해독기 규격을 모름"이라고 표시한다. 추측하지 않는다.
- 재계산 규칙: 틱 끝 시각 `e`(게임 시계)마다 `[e − W, e)` 창의 좌우 스파이크 수 `c_L`, `c_R`. 둘 다 `≥ n` → 점프, 왼쪽만 → 오른쪽, 오른쪽만 → 왼쪽, 둘 다 아님 → 없음. M7c 묶음에서 기존 결과(574/574, 196/196)가 그대로 나와야 한다.
- 주황/보라 분류 창을 해독기 `W`로 바꾼다. 범례와 설명 문구의 "50 ms"도 실제 값으로 표시한다.
- `meta.warmup_steps × dt`가 2,000 ms 이상이면 과도 구간 띠를 칠하지 않는다. 대신 "예열 N s 뒤부터 기록"을 표시한다. 없거나 작으면 지금처럼 칠한다. 통계 문구도 같은 조건으로 바꾼다.
- 머리말에 해독기를 한 줄로 보인다. 예: "해독기: 300 ms 안 같은 쪽 2발 (M7c2)" / "해독기: 50 ms 안 한 발 (M7c)".
- 테스트(`tests/test_3d_html.py`): 두 해독기 규격 읽기, 모르는 규격이면 검사 끔, 예열 묶음에서 띠 없음. 헤드리스로 M7c2 피하기 묶음을 열어 재계산 일치 수를 리포트에 적는다.
- 스크린샷: `docs/m7e2-rematch-dodge.png`(M7c2 피하기 v2 묶음).
