# M7 — 초파리 뇌 게임 사다리: 어디까지 깨나

총괄 세션 작성 (2026-10-23). 사용자 승인. **실행 전에 쓴 문서다.** 아래 규칙은 결과를 보고 바꾸지 않는다.

> **보고 대상:** 총괄 세션. 이 지시를 전달한 메시지의 `from-name`을 쓴다.

## 질문
**같은 초파리 뇌가, 같은 눈과 같은 근육으로, 어느 게임까지 통하는가.** 이기는 게임과 못 이기는 게임이 갈리는 지점을 숫자로 보여준다. 대부분의 게임에서 초파리가 무작위 봇과 비슷할 것이라는 게 기본 예상이고, 그것도 결과다.

## 남들 영상과 다른 점 (지켜야 할 규칙)
1. **같은 눈, 같은 근육.** 입력 경로와 출력 해독기는 한 번 정하면 모든 게임에서 바꾸지 않는다. 게임마다 뉴런 연결을 맞추면 사람이 공략을 짜는 것이고, 그건 이 프로젝트가 피하기로 한 임의 매핑이다(CLAUDE.md §4.4).
2. **비교 대상 셋을 항상 같이 돌린다.**
   - 무작위 봇: 같은 행동 공간에서 균일 무작위.
   - **뇌 없는 봇**: 초파리와 **똑같은 입력 신호**에 "임계값 넘으면 행동" 한 줄만 붙인 것. 임계값은 학습용 시드 0~9에서 가장 좋은 값으로 고르고 평가용 시드 10~19로 잰다. 초파리가 이 봇을 못 이기면 배선도가 한 일이 없다.
   - 아타리 게임은 공개된 인간·무작위 점수를 같은 표에 놓는다(그 숫자는 출처를 달아 인용만 하고 우리가 재지 않는다).
3. **학습 없음.** 배선도에 가소성이 없다. 같은 시드면 같은 판이 나온다. "연습해서 늘었다"는 장면은 만들지 않는다.
4. **지름길은 화면에 표시한다.** 시각엽을 거치지 않고 감지기를 직접 짜서 넣는 단계는 그렇다고 명시한다. 거기서부터 근육까지만 배선도다.
5. **점화 판정은 세 숫자 규칙**(대조군 절대 상태, 자극 런 절대 상태, 대조 대비 초과)을 쓴다. 뷰어의 실패 경고(발화 0 또는 90 % 이상)가 뜨는 판은 결과로 내지 않는다.
6. **게임 출처.** 직접 만든 게임, 또는 정식으로 배포가 허락된 롬만 쓴다. 원작 상표명은 제목에 쓰지 않는다.

## 데이터로 확인한 탈출 회로 (총괄이 조회함)
| 단계 | 유형 | 개수 (좌 / 우) | 다음 단계로의 연결 |
|---|---|---|---|
| 다가오는 물체 감지 | `LC4` | 71 / 55 | 같은 쪽 거대 신경섬유로만. 좌 3,782 · 우 2,580 접촉, 그 쪽 세포 전부 |
| 다가오는 물체 감지 | `LPLC2` | 94 / 91 | 같은 쪽 거대 신경섬유로만. 좌 2,642 · 우 2,220 접촉, 그 쪽 세포 전부 |
| 점프 명령 | `DNp01` (거대 신경섬유, instance `DNp01(GF)_L/_R`) | 1 / 1 | 출력 상위에 `TTMn` 90 접촉 |
| 점프 근육 운동뉴런 | `TTMn` | — | — |

거대 신경섬유가 받는 입력 1·2위가 `LC4`(6,362)와 `LPLC2`(4,862)다. 감지기 → 거대 신경섬유 → 운동뉴런이 **두 홉**이다. 청각에서 신호가 닿은 거리(홉 2)와 같다.

**주의(가정, 확인 필요).** 거대 신경섬유와 점프 운동뉴런 사이는 문헌상 전기 시냅스 비중이 큰 것으로 알려져 있는데, 커넥톰은 화학 시냅스만 센다. 우리 모델에서 이 연결이 실제보다 약할 수 있다. 그래서 첫 실험은 거대 신경섬유와 운동뉴런을 **둘 다** 읽는다.

## M7e 준비 결정 (2026-10-23, 조종석 창의 사전 검토 반영)

조종석 창이 분할 화면 지시서 전에 짚은 네 가지. 결정만 먼저 적고, 구현은 M7a·M7b가 끝난 뒤 담당 창에 배정한다(지금 그 파일들을 만지는 창은 없지만 두 창이 작업 중이라 끝난 뒤로 미룬다).

1. **프로브 프로필 도입.** 지금 집합 정의(`flysim/probe/sets.py`)는 청각 15집합 하나뿐이라 탈출 회로 뉴런이 전부 `rest`에 섞인다. 집합 정의를 이름 붙은 **프로필**로 바꾼다: 기존 것은 `auditory`, 새로 `escape`(LC4_L/R, LPLC2_L/R, DNp01_L/R, TTMn_L/R, rest). 기존 동작은 `auditory`가 기본값이라 그대로 유지(회귀 테스트). → `sets.py` 프로필은 M1 서버 창(서버와 run.json 내보내기용).
   **점구름(`export3d`)은 바꾸지 않는다** (조종석 창 제안 채택). 점구름 파일 이름이 계약에 고정(`/neurons-3d.{json,bin}`)이라 프로필별로 내면 청각 화면을 덮어쓰거나 계약을 고쳐야 한다. 대신 3D 화면이 집합 소속을 **재생 중인 run.json의 `neurons.region`/`regions`**(실시간이면 `hello.sets`, 탈출 집합은 전부 2,000개 이하라 인덱스가 실린다)에서 가져온다. 점구름은 위치 전용으로 쓰고, 그 안의 `set` 배열은 run.json이 없을 때의 기본값이다. → `flysim-3d.html` 쪽 일이므로 M7e에 포함.
2. **골격 CLI가 프로필을 받는다.** `flysim/data/skeletons.py --profile escape`로 LC4·LPLC2·DNp01·TTMn 묶음을 만든다. → M3 엔진 창.
3. **거대 신경섬유 신호 보장: 프로필 영역으로 해결.** 서버가 `escape` 프로필로 뜨면 `DNp01_L`·`DNp01_R`·`TTMn_*`가 각각 영역이 되어 `frame.rates`에 매 빈 실린다. 1개짜리 영역이면 발화율이 곧 스파이크다. 표본 상한과 무관해진다. "지정 뉴런은 표본에서 빼지 않는다" 계약 조항은 지금은 만들지 않는다(필요해지면 v1.3).
4. **분할 화면은 재생형부터.** 서버 없이 열리고 결과 재현 규칙과 맞는다. 실시간형(프로토콜에 게임 프레임 메시지 추가)은 그 다음. 한 판 묶음 형식은 M7e 지시서에서 정하되 뼈대는 이렇다:
   - `frames.npz` — `frames: uint8[T,84,84]`, `t_ms: float[T]` (틱마다 1/60 s)
   - `run.json` — 기존 뷰어 계약 그대로(빈 1 ms), `escape` 프로필 영역
   - `game.json` — 점수, 사건 목록(점프·충돌·통과, 각 `t_ms`), 에이전트 종류, 시드
   시간 정렬은 `t_ms` 하나로 한다. 화면은 현재 시각 이하의 마지막 게임 프레임을 띄운다.
