# M6c 구현 지시서 — 3D 뉴런 뷰어 (`flysim-3d.html`)

총괄 세션 작성 (2026-09-18).

> **보고 대상:** 총괄 세션. 세션 이름은 재시작마다 바뀌므로 이 지시를 전달한 메시지의 `from-name`을 쓴다.

먼저 읽을 것: `CLAUDE.md` §5.5, **`docs/m6-3d-contract.md`(계약, 수정 금지)**, `flysim-viewer.html` 전체(시각 언어를 이어받되 **수정 금지**), `flysim-live.html`(정규화·경고 처리 방식 참고, **수정 금지**).

의존성: 없음. **단일 HTML 파일, 외부 스크립트 금지.** three.js를 포함한 어떤 3D 라이브러리도 쓰지 않는다. **WebGL2를 직접** 쓴다(폰트 링크만 허용). 이유: 지금까지의 모든 화면이 무의존 단일 파일이고 그 성질을 유지한다.

## 만들 것
`flysim-3d.html` — 뉴런을 3차원으로 보여주고 활동을 재생한다.

1. **점구름**: 계약 파일 1을 읽어 165,122개 뉴런을 점으로 그린다. NaN 좌표는 버린다. `gl.POINTS`, 크기는 거리에 따라. 기본은 어둡게 깔고, 발화한 뉴런만 밝게(기존 뷰어의 잔광 감쇠 방식을 3D로 옮긴다).
2. **골격**: 계약 파일 2를 읽어 `gl.LINES`로 겹쳐 그린다. 집합별로 켜고 끈다. 파일이 없으면 그 토글을 비활성으로 두고 안내만 띄운다(오류 아님).
3. **카메라**: 궤도 회전(드래그), 줌(휠), 패닝(Shift+드래그). 정면·측면·윗면 프리셋 버튼. 자동 회전 토글.
4. **활동 재생**: `run.json`을 드래그&드롭으로 받는다(기존 뷰어와 같은 방식). 재생/정지, 스크럽, 속도. 기존 뷰어의 실패 감지 문구를 그대로 쓴다(발화 0, 90% 초과).
5. **집합 색**: 계약의 `sets` 순서를 그대로 쓴다. 차가운 색 = 입력, 따뜻한 색 = 출력이라는 기존 규칙을 잇는다.
6. **모의 모드**: 서버·파일이 없어도 되도록 `?mock=1`로 합성 점구름과 합성 골격을 만들어 붙인다. 조종석의 모의 서버와 같은 발상이고, **합성 데이터임을 화면에 빨간 배지로 표시**한다. 개발·검증은 이 모드로 한다.

## 성능
- 점 165k는 버퍼 한 번 올리고 매 프레임 색만 갱신한다. 프레임마다 전체를 다시 올리지 않는다.
- 선분은 집합당 한 버퍼. **실제 규모는 네 집합 합쳐 약 97만 선분, 23 MB다**(계약 v1.1 확정치: JO_AB 0.25 MB · AMMCtype 3.3 MB · pC1 5.9 MB · WED 13.9 MB). 100만 선분에서 60 fps를 목표로 하고 측정치를 리포트에 적는다. 못 미치면 집합 토글로 끄게 두고 수치를 보고한다.
- 골격 json의 `soma`는 **null일 수 있다**(JO_AB는 114개 전부 null). 계약에 없는 키가 있어도 무시하고 진행한다.
- `prefers-reduced-motion`이면 자동 회전을 끈다.
